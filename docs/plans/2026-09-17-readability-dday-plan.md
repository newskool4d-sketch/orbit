# Orbit 글자 크기·D-day 개선 계획

작성일: 2026-09-17

상태: 1~3단계 소스 구현 후 4단계 통합 검증을 진행함. 전체 판정은 PARTIAL이며 최신 근거는 [통합 검증 보고서](2026-09-17-integration-verification.md)에 기록함. 설치본 교체·커밋·푸시는 수행하지 않음.

1~3단계 당시 실행 메모(4단계 결과는 통합 검증 보고서 참조): 변경 전 Windows 소스 빌드본과 변경 후 560×700 CSS 뷰포트·Windows 배율 125% 조건의 `보통 / 크게 / 더 크게` 화면을 각각 700×875 이미지로 캡처해 비교했다. D-day에는 직접 등록·편집·중요 표시·정렬·보관·복원·제목 확인 삭제, 로컬 원자 저장, 손상 파일 보존, 오늘 화면 최대 3개 표시를 구현했다. 공용 JavaScript 시험 22개가 통과했다. 기존 Windows 시험 스크립트도 종료 코드 0이었지만 이전 빌드 바이너리를 사용했으므로 새 C# D-day 저장소 검증으로 보지 않는다. 현재 PC에는 .NET SDK 10.0.400이 없어 변경된 네이티브 C#의 재빌드와 실제 재시작 복원이 미검증이며, macOS 실제 빌드도 미검증이다.

## 1. 권장 방향

1. 본문 기본값을 12px에서 14px로 높이고, 보조정보를 12px로 정리한다.
2. 설정에 `보통 / 크게 / 더 크게`를 제공하고, 크기에 맞게 카드 배치와 줄바꿈을 조정한다.
3. Google 연결 없이 중요한 날짜를 직접 등록하는 D-day를 우선 구현한다.
4. 오늘 화면에는 D-day를 최대 3개 표시하고 나머지는 전체 목록에서 관리한다.
5. Google 연동 D-day와 알림·반복일 기능은 후속 단계로 구분한다.

현재 디자인의 Moss·Pearl·Midnight 색상 체계와 기존 탭을 유지한다. Windows를 우선 확인하되, 공용 Resources를 사용하는 macOS의 설정·브리지 호환성을 함께 설계한다. 신규 외부 런타임 의존성은 추가하지 않는다.

## 3. 글자 크기 및 배치

아래 값은 시안의 시작값이며 사용성 확인 뒤 확정한다. CSS px와 Windows DIP/OS 배율을 구분해 검증한다.

| 역할 | 현재 대표값 | 보통·권장 기본 | 크게 | 더 크게 |
| --- | --- | --- | --- | --- |
| 본문·할 일·파일·일정 제목 | 11~12px | 14px | 16px | 18px |
| 시간·날짜·출처·상태 | 9~10px | 12px | 14px | 16px |
| 탭·주요 버튼·설정 항목 | 11~12px | 14px | 16px | 18px |
| 다음 일정 제목 | 17px | 18px | 20px | 22px |
| 인사말 | 26px | 26px | 28px | 30px |

- `--font-body`, `--font-meta`, `--font-title` 등 역할별 변수를 적용한다. 현재 산재한 고정 크기를 치환하되 색상·장식은 유지한다.
- 본문 행간은 1.5 전후로 설정한다. 제목이 길면 카드 높이가 늘어나게 하고 시간·D-day 배지가 제목을 밀어내지 않게 한다.
- `크게` 이상에서 오늘 화면의 파일·AI 카드도 1열로 전환한다. 캘린더 시간 열은 고정 83px에 의존하지 않고 필요하면 제목 위로 이동한다.
- 인사말 주변 여백을 줄여 실사용 정보를 위한 공간을 확보한다. 버튼과 입력 영역은 글자 확대에 맞춰 커지게 한다.
- 잘린 제목은 마우스 호버뿐 아니라 키보드 포커스·상세 보기로도 전체 내용을 확인할 수 있게 한다.
- 설정에서 크기를 선택하면 즉시 반영하고 재실행 후에도 유지한다. 저장에 실패하면 실패를 알리고 실제 저장 상태와 화면 상태가 어긋나지 않게 한다.
- 기존 사용자 설정에 새 필드가 없으면 `보통`으로 읽는다. 테마·폴더 등 기존 설정값을 유지한다.
- 3단계 선택은 편의 기능이다. 이것만으로 200% 확대 지원을 충족했다고 보지 않는다. 호스트의 확대 수단을 확인하고 필요하면 별도 확대 제어를 제공한다.

확대 검증의 참고 기준은 200%까지 내용·기능 손실 없이 사용할 수 있어야 한다는 [W3C Resize Text 안내](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)다. 본 계획에서는 검증 목표로 사용하며 접근성 준수 판정을 내리지 않는다.

## 4. D-day 대안과 권장 범위

| 대안 | 장점 | 제약 | 판단 |
| --- | --- | --- | --- |
| 기존 Google 항목에 배지만 추가 | 변경 규모가 작음 | 연결 필수, Calendar 7일 제한, Tasks 날짜 의미 주의 | 후속 표시 개선으로 적합 |
| Orbit에 제목·날짜 직접 등록 | 연결 없이 사용, 장기 날짜 지원, 동작이 명확함 | 등록·편집·보관·저장 기능 필요 | 1차 권장 |
| 직접 등록 + Google 지속 연동 | 입력 중복 감소 | 안정적 ID, 조회 범위, 삭제·변경·동기화 실패 처리 필요 | 후속 단계 |

### 1차 기능

- 제목과 기준 날짜를 입력해 추가한다. 제목은 공백만 입력할 수 없고 날짜는 실제 존재하는 날짜여야 한다.
- 편집, 중요 표시, 보관·복원, 삭제를 제공한다. 삭제는 대상 제목을 보여 주는 확인 절차를 둔다.
- 오늘 화면에서 다음 일정 바로 아래에 `중요 날짜` 영역을 배치한다. 별도 상위 탭은 늘리지 않는다.
- 표시 예: `D-7 · 제출 예정 · 9월 24일`, `D-day · 발표 · 오늘`, `D+2 · 검토 · 2일 지남`. 예시는 합성 데이터다.
- 기본 표시 순서는 중요 표시 항목 우선, 각 그룹에서는 미래·당일 항목을 날짜순으로 표시한다. 지난 날짜는 별도 그룹에 경과 일수가 적은 순서로 정리한다. 동률은 생성 순서로 고정한다.
- 오늘 화면은 위 순서의 최대 3개와 `전체 보기`를 제공한다. 전체 목록에서 지난 날짜·보관 항목까지 확인할 수 있다.
- 지나간 날짜를 자동 삭제하지 않는다. 등록 항목이 없으면 간단한 설명과 `날짜 추가`를 보여 준다.
- 임박·당일·경과 상태를 색상과 문자로 함께 표시한다. 소리·OS 알림·상시 백그라운드 실행은 1차 범위에 넣지 않는다.

### 날짜 계산 규칙

- 미래는 D-N, 당일은 D-day, 과거는 D+N으로 표시한다. 오늘을 D-1로 세지 않는다.
- 날짜는 `YYYY-MM-DD`로 저장하고 남은 일수는 저장하지 않는다.
- 현재 기기의 현지 날짜를 오늘의 기준으로 삼는다. 대상 날짜와 오늘의 연·월·일을 날짜 순번으로 바꿔 차이를 구한다. 경과 밀리초를 24시간으로 나누는 방식은 사용하지 않는다.
- 자정, 패널 재열기, 절전 복귀, 시간대 변경을 반영한다. 숨김 상태에서 계산을 위한 상시 폴링을 추가하지 않는다.
- 월말·연말·윤년·DST·날짜 변경선을 넘는 시간대 변경을 시험한다.

### Google 항목의 의미

Google Tasks의 `due`는 공식 문서상 할 일을 수행하거나 캘린더에 표시할 **예정일**이며 마감 시한을 뜻하지 않는다. 시간 정보도 읽거나 쓸 수 없다. 현재 앱의 `오늘 마감`·`기한 지남`은 `오늘 예정`·`예정일 지남`으로 고치는 것을 관련 개선에 포함한다. [Google Tasks 공식 문서](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks)

후속 연동에서는 Calendar를 `일정까지 N일`, Tasks를 `예정일까지 N일`로 표시한다. 완료된 Tasks에는 진행 중인 카운트다운을 붙이지 않는다. 날짜 없는 Tasks는 D-day 계산에서 제외한다.

Calendar의 7일 제한은 현재 앱의 조회 정책이다. 장기 연동 단계에서는 확장 조회 또는 선택한 일정의 별도 추적을 설계하고, 오늘 화면과 기존 7일 목록의 의미는 유지한다. 조회 범위를 늘릴 때 페이지 처리와 갱신 비용을 함께 확인한다. [Google Calendar 조회 API](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)

## 5. 저장과 플랫폼 적용

- 글자 크기는 Windows의 기존 설정 저장소와 macOS Preferences에 저장한다. WebView의 localStorage에 영속성을 의존하지 않는다.
- D-day는 Orbit 소유의 로컬 파일에 저장한다. Windows는 기존 앱 데이터 루트 아래, macOS는 앱 전용 Application Support 아래에 버전 있는 문서로 보관한다.
- 최소 데이터는 `schemaVersion`, 항목별 `id`, `title`, `targetDate`, `pinned`, `archived`, `createdAt`, `updatedAt`이다. 계산 결과는 화면 표시 때 생성한다.
- 임시 파일 후 교체하는 저장 방식과 읽기 실패 처리를 마련한다. 손상 파일을 빈 목록으로 자동 덮어쓰지 않는다.
- 브리지에 크기 변경과 D-day 관리 동작을 명시적으로 추가한다. 네이티브에서 값·날짜·항목 ID를 검증하고 제목은 화면에서 텍스트로 처리한다.
- 기능 지원 여부를 snapshot의 capability로 전달한다. 이전 호스트에서는 새 버튼을 숨기고 누락 필드를 안전한 기본값으로 처리한다.
- Google·Drive·Obsidian·AI 기록에는 쓰지 않는다. D-day의 날짜·제목을 진단 로그나 외부로 전송하지 않는다.
- 각 기기에 로컬 저장하므로 Windows와 macOS 사이의 동기화는 제공하지 않는다는 점을 설정 안내에 명시한다.

예상 변경 지점: `Resources/style.css`, `calendar.css`, `index.html`, `app.js`, `platform.js`; Windows `Settings.cs`, `Program.cs`, `Policies.cs` 및 D-day 저장 모듈; macOS `Models.swift`, `Bridge.swift` 및 저장 모듈. Google 연동 확장은 1차 완료의 필수 조건이 아니다.

- 저장: 구형 설정 로드, 크기·날짜 재시작 복원, 잘못된 필드, 저장 실패, 손상 파일 보존.
- UI: 세 테마 × 세 크기, Windows OS 배율 100/125/150/200%, 별도의 텍스트 200% 확대 경로, 작은 작업 영역, 설정 내부 스크롤.
- 접근: 키보드 탭 순서, 입력 오류 읽기, 편집창 닫은 뒤 포커스 복귀, 색상 없이 상태 구분, 잘린 제목의 전체 확인.

- Windows: `Windows/scripts/build.ps1` 후 `Windows/scripts/test.ps1 -NativeUi`. SDK 경로는 실행 시 확인한다.
- macOS: macOS 환경에서 `bash scripts/build.sh`, `build/Orbit.app/Contents/MacOS/Orbit --self-test`, 공용 UI 실제 표시 확인.
- 공용 JS: `node --test tests/web.test.cjs tests/platform.test.cjs tests/windows-ui.test.cjs`와 날짜·저장 계약에 맞는 추가 시험.

1~3단계 구현과 실행 가능한 4단계 소스 검증을 진행했다. 최신 시험 결과와 남은 Windows/macOS·실제 화면 검증은 통합 검증 보고서를 따른다. 실제 Google 쓰기·설치본 교체·커밋·푸시는 수행하지 않았다.
